What's in ZoomLens today, and what's a concept

In ZoomLens today

  • Describe screen and Explain this
  • Typed questions, and follow-ups that build on the last answer
  • Answers only you see, without the presenter being told

Concepts shown here

  • Selecting part of the screen, or drawing a box around it
  • Answers that link back to the screen
  • Suggested questions
  • Noticing screen changes and catching you up

ZoomLens reads the screen at the moment you ask and does not track how it changes over time. Catching you up would mean keeping recent screens, which raises privacy questions that would need answers first.

What is guaranteed

  • Answers reach only the person who asked. Every message the server sends is addressed to exactly one session. There is no broadcast anywhere.
  • A reply cannot be redirected. The server refuses to deliver an answer unless it matches a request that session actually made.
  • Enforced on the server, not the panel. Anything enforced in the panel could be changed by whoever runs it.
  • Tested, including against its own failure. Seven cases, including ten participants asking at once. The protection was deliberately broken to confirm the tests catch it.

What is not

  • The presenter is not notified. That is deliberate, and it is the main open question for ethical review.
  • Screen images go to a third-party model to be interpreted, without filtering.
  • Participant identity comes from the panel and is not yet independently verified.

Engineering

Behind the meeting window.

Here is what the user sees. This is what is happening underneath, and what was hard about it. Pick a problem and try it.

A video stream is not a stack of pictures

    Problem
    Shared screens arrive as H.264, where one keyframe is a full image and everything after it is only a change. A single frame on its own is not decodable.
    Implementation
    An in-memory buffer keeps the latest parameter sets plus everything since the most recent keyframe, so it always holds a decodable clip. Two bugs surfaced: keyframes split across several units were being cut to their last fragment, and data arriving in chunks broke wherever a boundary fell across two.
    Tradeoff
    Memory is capped by size rather than count, and drops back to the keyframe when exceeded, so a busy screen costs more memory but never produces an undecodable image.

    Privacy has to live where it cannot be edited

    ServerOne send function, addressed to one session
      Problem
      The promise is that your answers reach you and nobody else. A promise enforced in the browser can be undone by whoever controls the browser.
      Implementation
      Every connection is bound to one participant when it opens. One function is the only way a message leaves the server, and it takes a session, not a socket. Replies are refused unless the request is outstanding on that session.
      Tradeoff
      Messages that several people need, such as a screen share starting, are sent to each person individually. Slower than broadcasting, but there is no broadcast to misuse.

      A meeting stream that would not start

      Answer source
      Problem
      Reading the meeting's media stream needs a capability enabled on the Zoom account. Requests to start it were accepted and then nothing arrived.
      Implementation
      Three sources, tried in order of how close each is to the real thing: the meeting stream, then the participant's own display, which works because Zoom draws the shared screen there, then a recording. Every answer says which source it used.
      Tradeoff
      Reading the display only sees what that machine sees, so it cannot run on a server. It is a bridge until the stream is enabled, and it is labelled as one.

      Limits that a reload cannot reset

      Questions today0 / 60

      Ask a few times, then try reopening the panel.

      Problem
      Every question costs money and several seconds. Nothing stopped someone pressing the button repeatedly.
      Implementation
      A minimum gap between one participant's requests and a daily ceiling, counted per participant rather than per connection, so closing and reopening the panel does not start the count again.
      Tradeoff
      A genuine second question within a few seconds is refused. The panel says how long to wait rather than failing silently.

      An assistant that described itself

      What the display capture contains: the shared slide, and the ZoomLens panel beside it.

      Example answer

      Problem
      Reading the whole display captures the ZoomLens panel too, and early answers dutifully described the panel back to the person reading it.
      Implementation
      The model is told explicitly that the image may contain the meeting window, participant tiles and the ZoomLens panel, and to describe only what is being presented.
      Tradeoff
      It relies on an instruction rather than cropping. Cropping would be more certain but needs to know where the shared content sits, which varies by layout.

      Each panel is a small simulation of the mechanism, run in your browser. Answers in it are examples.

      The pipeline

      A question travels from the panel to the server, which captures the shared screen, turns it into an image, asks a vision model, and returns the answer to the one person who asked.

      Node, Express and WebSockets on the server. Plain HTML, CSS and JavaScript in the panel, loaded by the Zoom Apps SDK. Source on GitHub.

      Questions

      What people ask first.

      Does the presenter know I'm asking?

      No. ZoomLens does not notify the presenter, and your questions and answers are sent only to you. Whether presenters should be told is the main open question for ethical review.

      Can other people in the meeting see my questions?

      No. Every message the server sends is addressed to one session, and there is no broadcast. This is tested with ten participants asking at the same moment.

      What gets sent to the AI model?

      One still image of the shared screen and your question. They go to a third-party vision model to be answered, and the image is not filtered first.

      Is the meeting recorded?

      Recent screen video is kept in memory so an image is ready when you ask. During development, video from the meeting stream is also saved to a file on the developer's machine. That has to change before wider use, and the privacy notes in the repository say so.

      Is there a limit on questions?

      Yes. Each question is a paid call to the model, so each person can ask once every few seconds and up to a daily limit. The panel says how long to wait instead of failing silently.

      Can I use it in my own meetings?

      Not yet. ZoomLens is in development and runs on a test Zoom account. The demo at the top of this page shows how it works, and the source is on GitHub.
