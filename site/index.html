What's in ZoomLens today, and what's a concept

In ZoomLens today

  • Describe screen, Explain, and What changed?
  • Typed questions, and follow-ups that build on the last answer
  • Announce changes and Color Assist
  • Answers only you see, without the presenter being told

Concepts shown here

  • Selecting part of the screen, or drawing a box around it
  • Answers that link back to the screen
  • Suggested questions
  • A notice when the screen changes; the panel describes the change instead when Announce changes is on

ZoomLens only watches for changes while Announce changes or Color Assist is on. To notice a change it keeps a 64 by 36 grey thumbnail of the last screen it described, not a recording.

Accessibility

For when seeing the screen isn't enough.

Blind and low vision

Turn on Announce changes and ZoomLens describes each new slide out loud through your screen reader, without you having to ask.

Color blindness

Turn on Color Assist and ZoomLens tells you what the colors on screen mean, such as which numbers are good news and which are bad.

Both modes are new and haven't yet been tested with blind or color-blind users.

Privacy

Your answers reach only you.

Protected

  • Answers go to the person who asked. The server sends each answer to exactly one person.
  • Others never see it. Your questions and answers do not appear in the meeting, for other participants or the presenter.
  • Who's asking is checked with Zoom. Zoom confirms who each person is, so nobody can pretend to be you and read your answers.
  • Your questions aren't logged. The server notes that a question was asked, never what it said.
How the routing is enforced

Every connection is bound to one participant when it opens. A single function is the only way a message leaves the server, and it takes a session, not a socket, so there is no broadcast. A reply is refused unless that session made the request. Seven automated cases run against the real server, including ten participants asking at once, and the protection was deliberately broken to confirm the tests catch it. Who each connection belongs to comes from Zoom's encrypted app context, checked on the server, never from what the panel says about itself.

Full data handling: docs/privacy.md

Engineering

Behind the meeting window.

Three problems ZoomLens had to solve, each with a small demo you can try.

Turning video into a picture

Problem
Zoom sends a shared screen as video, and most of that video only records what changed. You can't grab one piece of it and get a picture.
Solution
ZoomLens keeps a short stretch of video, back to the last full picture, and turns it into an image only when you ask.

    F a full picture · C only what changed · S setup

    More detail
    Problem
    Shared screens arrive as H.264, where one keyframe is a full image and everything after it is only a change. A single frame on its own is not decodable.
    Implementation
    An in-memory buffer keeps the latest parameter sets plus everything since the most recent keyframe, so it always holds a decodable clip. Two bugs surfaced: keyframes split across several units were being cut to their last fragment, and data arriving in chunks broke wherever a boundary fell across two.
    Tradeoff
    Memory is capped by size rather than count, and drops back to the keyframe when exceeded, so a busy screen costs more memory but never produces an undecodable image.

    Most of an answer's wait is the model, not the capture: the panel is set to expect about 6 seconds for Describe and 12 for Explain.

    Source: framebuffer.js, decode.js

    Answers reach only you

    Problem
    Everyone in the meeting runs their own copy of ZoomLens, and anyone could tamper with theirs.
    Solution
    The server, not the panel, decides who gets each answer. It checks with Zoom who is asking, and sends every answer to that one person.

      More detail
      Problem
      The promise is that your answers reach you and nobody else. A promise enforced in the browser can be undone by whoever controls the browser.
      Implementation
      Every connection is bound to one participant when it opens. One function is the only way a message leaves the server, and it takes a session, not a socket. Replies are refused unless the request is outstanding on that session.
      Tradeoff
      Messages that several people need, such as a screen share starting, are sent to each person individually. Slower than broadcasting, but there is no broadcast to misuse.

      Limits that a reload cannot reset

      Problem
      Every question costs money and several seconds. Nothing stopped someone pressing the button repeatedly.
      Implementation
      A minimum gap between one participant's requests and a daily ceiling, counted per participant rather than per connection, so closing and reopening the panel does not start the count again.
      Tradeoff
      A genuine second question within a few seconds is refused. The panel says how long to wait rather than failing silently.

      Source: relay.js, test-isolation.js. Protocol: docs/protocol.md

      Noticing changes and colors

      Problem
      Describing the screen every few seconds would be slow and costly, and a warning about colors only helps when they could really be confused.
      Solution
      ZoomLens compares tiny snapshots of the screen to spot real changes, and checks how its colors look to people with color blindness. Only then does it ask the AI.

      More detail
      Problem
      A screen counts as changed when something a viewer would notice moved, not when a cursor drifts or the video recompresses. And many screens use several colors without relying on them.
      Implementation
      Each look shrinks the screen to 64 by 36 in grey and compares it with the last screen described: a moving pointer touches about 2 of 2,304 cells, one added bullet about 40. A change must hold still for one more look before it counts. For color, strongly colored pixels are grouped by hue, each color is passed through the Machado, Oliveira and Fernandes simulation of protanopia, deuteranopia and tritanopia, and pairs are compared with CIEDE2000, which matches the published test values. A pair that is clearly different normally but under 10 apart when simulated is flagged.
      Tradeoff
      The simulation models full color blindness, which most people don't have, and it isn't a medical measure. Window buttons and tab icons are colored too, so a note needs more than a few small marks of each color.

      Source: change.js, colors.js, watch.js. Measurements: docs/accessibility.md

      Questions

      What people ask first.

      Can I use it in my own meetings?

      Not yet. ZoomLens is in development and runs on a test Zoom account. The source is on GitHub.

      Does the presenter know I'm asking?

      No. ZoomLens does not notify the presenter, and your questions and answers are sent only to you. Whether presenters should be told is the main open question for ethical review.

      Can other people in the meeting see my questions?

      No. Every message the server sends goes to one person, and there is no way to send to everyone. This is tested with ten participants asking at the same moment.

      What gets sent to the AI model?

      One still image of the shared screen and your question. They go to a third-party vision model to be answered, and the image is not filtered first. With Announce changes or Color Assist on, a still is also sent when the screen changes in a way worth describing, at most once every 10 seconds; for Color Assist, only when its own analysis finds colors that could be confused.

      Is the meeting recorded?

      No. Recent screen video is kept in memory so an image is ready when you ask. Nothing is saved to disk unless a developer turns that on for testing.

      Does it work with a screen reader?

      Yes. Answers appear in a region screen readers announce as they arrive, the accessibility options are real switches, and every control works from the keyboard. With Announce changes on, you hear about a new slide without having to ask.

      Can it help if I'm color blind?

      That's what Color Assist is for. It names things by label instead of color and explains what each color means. The server works out which colors could be confused before asking the model, using simulated color blindness and a standard measure of color difference.

      Is there a limit on questions?

      Yes. Each question is a paid call to the model, so each person can ask once every few seconds and up to a daily limit. The panel says how long to wait.
